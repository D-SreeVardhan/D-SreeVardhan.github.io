01

SafeMolGen-DrugOracle

Closed-loop drug-discovery pipeline

Dec 2025 – Present

Base generator reached 68.8% chemical validity and 100% uniqueness on 2.85M ChEMBL molecules; RL refinement lifted mean clinical quality from 4.8% to 35.9% — about a 7.5× improvement over the published GRU baseline.

Validity
68.8%
Uniqueness
100%
Corpus
2.85M
ADMET ends
22
  1. Predict. A 3-layer Graph Isomorphism Network with attention pooling jointly predicts 22 ADMET endpoints from the Therapeutics Data Commons benchmark.
  2. Judge. Cascaded Phase I/II/III heads — each consumes the previous — plus a SMARTS filter for PAINS and known toxicophores.
  3. Generate. Causal Transformer over a regex SMILES tokenizer, conditioned on a 25-dimensional ADMET-plus-phase vector.
  4. Refine. REINFORCE and PPO under a validity-gated composite reward of validity, drug-likeness, oracle score, and diversity.

What I learned. The oracle’s reward contribution was an order of magnitude smaller than the validity term. Scaling it up collapsed validity to zero — the policy drifted off the manifold of valid chemistry. The fix is a curriculum on the oracle weight plus a divergence penalty against the pretrained policy: the same shape as RLHF.

Multilingual Voice Chatbot

Cross-lingual speech-to-speech across five languages

Dec 2025 – Apr 2026

One English-pivot answering stage serves all 25 input–output language pairs across Hindi, Tamil, Telugu, Kannada, and English, reaching roughly 82% answer relevance on a 200-query development set.

Languages
5
Pairs
25
Relevance
~82%
Dev queries
200
  1. One mapping for language. Recognition wants ISO, translation wants FLORES, TTS is per-language — all three read from a single table, so a sixth language is one config entry.
  2. Memory in the pivot. History is stored in English, so context survives when a follow-up arrives in a different language.
  3. Voices chosen for the language. Indic Parler-TTS for Indic pronunciation; Coqui VITS for English.
  4. Built for a live demo. Process-level model cache, stage-by-stage streaming, and explicit offline fallbacks.

The trade-off. Pivoting twice compounds translation error, and code-mixed speech — how people actually talk in Bengaluru — is the hardest input for both the recogniser and the translator. The honest boundary is monolingual utterances.

03

Legal Document Classifier

Retrieval-grounded document intelligence

Mar 2026 – Apr 2026

Owned the retrieval layer of a two-person build. Legal-BERT fine-tuned across 10+ categories reached an F1 of 0.89; every answer returns the clauses and scores it was grounded on.

Held-out F1
0.89
Categories
10+
Team
2
  1. Chunking that respects clauses. Paragraphs windowed with deliberate overlap so a clause on a boundary is never lost from both halves.
  2. Dense ranking, sparse safety net. MiniLM embeddings by cosine similarity, falling back to TF-IDF when the embedding model is unavailable.
  3. No vector database, on purpose. One uploaded document is a few hundred chunks — exact search is a matrix multiply. A vector store would add persistence and staleness for no gain.
  4. Classification. Legal-BERT with the label mapping persisted beside the checkpoint, plus a BiLSTM baseline for comparison.
