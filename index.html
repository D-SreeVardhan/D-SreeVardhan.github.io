01

SafeMolGen‑DrugOracle

Closed-loop drug-discovery pipeline

Dec 2025 – Present

Most molecular generators optimise one surrogate score and hope the chemistry holds up. SafeMolGen treats the problem as a loop instead: a Transformer proposes drug-like molecules, an oracle estimates whether each would survive clinical trials, and the oracle’s verdict is fed back as a conditioning signal so the next round of proposals is steered toward safer chemistry. Every iteration streams to the browser as it happens.

  1. Predict. A three-layer Graph Isomorphism Network with attention pooling reads the molecule as a graph and jointly predicts 22 ADMET endpoints from the Therapeutics Data Commons benchmark group, spanning both regression and classification.
  2. Judge. DrugOracle scores Phase I/II/III survival with cascaded heads — Phase II consumes Phase I’s output and Phase III consumes both — because trials are sequential, not independent. A SMARTS filter flags PAINS and known toxicophores alongside it.
  3. Generate. A causal Transformer over a regex SMILES tokeniser that keeps multi-character atoms and ring closures as single tokens, pretrained on 2.85M ChEMBL molecules and conditioned on a 25-dimensional ADMET-plus-phase vector.
  4. Refine. REINFORCE and PPO fine-tuning under a composite reward of validity, drug-likeness, oracle score, and diversity — with the oracle term gated on validity so invalid molecules can never accrue reward.

What I learned the hard way. The oracle’s contribution to the reward was an order of magnitude smaller than the validity term, so it barely registered. Scaling it up to compensate collapsed validity to zero — the policy drifted clean off the manifold of valid chemistry with nothing anchoring it back. The fix is a curriculum on the oracle weight plus a divergence penalty against the pretrained policy, which is exactly the shape of the problem RLHF solves in language models. Reward scaling is not a detail.

02

Multilingual Voice Chatbot

Cross-lingual speech-to-speech across five languages

Dec 2025 – Apr 2026

Ask a question out loud in Hindi, Tamil, Telugu, Kannada, or English and get a spoken answer back in whichever of those you choose. The interesting constraint is that the answering model is far stronger in English than in any Indic language, so the system pivots: translate in, answer once, translate out. One good reasoning stage serves all 25 input–output pairs instead of five weak ones.

  1. One source of truth for language. Speech recognition wants ISO codes, translation wants FLORES codes, and the voice model is chosen per language. All three read from a single mapping, so adding a sixth language is one configuration entry rather than a change across five modules.
  2. Memory in the pivot language. Conversation history is stored in English, which is why context survives when someone asks their follow-up in a different language from the original question.
  3. Voices chosen for the language, not the stack. AI4Bharat’s Indic Parler-TTS handles Indic pronunciation and prosody; a Coqui VITS voice handles English.
  4. Built to survive a live demo. Several gigabytes of weights stay resident in a process-level cache across requests, each stage streams to the browser as it completes, and every component has an explicit fallback for offline or missing-model conditions.

The trade-off worth naming. Pivoting twice means translation error compounds, and code-mixed speech — which is how people actually talk in Bengaluru — is the hardest input for both the recogniser and the translator. The honest boundary of this system is monolingual utterances.

03

Legal Document Classifier

Retrieval-grounded document intelligence

Mar 2026 – Apr 2026

A two-person build where I owned the retrieval layer. Classification alone tells a lawyer what a document is; it does not tell them why the model thinks so. So every generated answer here comes back with the clauses it was grounded in and their relevance scores, which makes a prediction something you can check rather than something you have to trust.

  1. Chunking that respects clauses. Paragraphs are windowed with deliberate word overlap, so a clause straddling a boundary is never lost from both halves — the failure mode that quietly wrecks naive chunking.
  2. Dense ranking with a sparse safety net. MiniLM sentence embeddings ranked by cosine similarity, falling back to TF‑IDF so the system keeps answering when the embedding model is unavailable.
  3. No vector database, on purpose. The corpus is one uploaded document. Exact search over a few hundred chunks is a single matrix multiply; a vector store would add a dependency, a persistence story, and index staleness for no measurable gain. That calculus flips the moment the corpus outgrows memory.
  4. Classification. Legal‑BERT fine-tuned across 10+ document categories, with the label mapping persisted beside the checkpoint so inference reproduces training classes exactly, and a BiLSTM baseline kept for comparison.

Research

IEEE CONECCT 2026 · Accepted, in publication

Molecular Generation for Drug Discovery: A Lightweight GRU-Based Approach for Property-Guided Drug Discovery

12th IEEE International Conference on Electronics, Computing & Communication Technologies · May 2026

A parameter-efficient GRU generator over SMILES, conditioned on QED, LogP, and molecular weight. The argument is that property-guided molecular generation does not require large-scale compute — a small recurrent model, conditioned well, gets you a usable baseline. That baseline is what SafeMolGen is measured against.

Approach

I care about the line between what a model learned and what I hand-wrote.

Most of my systems are part learned and part policy. SafeMolGen’s clinical quality score is a weighted sum with safety penalties I chose — not a learned head — and I keep that written down, because a heuristic dressed up as a model is how teams end up trusting a number nobody validated.

The corollary is that I read my own evaluations even when they disagree with the story I wanted to tell. Several ADMET endpoints in SafeMolGen sit near chance, because the splits are small and scaffold-split and training was CPU-bound. That is worth knowing and saying out loud. A negative result I can explain is more useful than a number I can’t source.

And I finish things. Each project here is a running service with tests and CI, not a notebook — because the interesting failures only show up once something is deployed and a person is waiting on it.
